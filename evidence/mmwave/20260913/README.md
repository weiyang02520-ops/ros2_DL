# 毫米波资料核验（2026-09-13）

## 结论

用户提供的目录包含毫米波雷达的厂商资料、上位机和串口驱动，已经足以确认一条候选的串口协议方向；目录中没有发现可直接作为“真实采集数据”的 CSV、BIN、DAT、LOG 或串口原始字节记录。因此当前状态为：**协议资料已确认，真实数据待采集**。

这批资料不能单独证明某一块实物的准确型号、固件版本、实时输出字节流或 ROS 2 实时接入已经完成。产品介绍 PDF 同时列出多种 60/77 GHz 型号，必须在接线后从设备标签、上位机识别信息或原始帧中确认具体型号。

## 已确认的协议要点

来自 `4D成像雷达使用说明（上手必看）.pdf` 的 Demo 输出协议表：

- 串口：3,000,000 baud，8 数据位，1 停止位，无校验（8N1）。
- 帧包头：`0xFFEEFFDC`。
- 帧包尾：`0xFFEEFFD3`。
- 点云包头：`0xFFDDFECB`。
- 点云坐标 X/Y/Z：`int16`，单位 `0.001 m`。
- SNR：`uint16` 线性值，资料说明为相对大小，不是绝对 dB。
- 速度：`int16`，单位 `0.1 m/s`。
- 帧头还包含帧周期、各类点数、帧号和处理时间等打包字段。
- 资料还给出航迹包，但航迹包的实际使用必须以设备型号和原始帧验证为准。

## 与当前 ROS 2 接口的关系

当前开发分支已经有规范化输入接口：

- `/dg/mmwave/points`：`sensor_msgs/PointCloud2`。
- `/dg/mmwave/quality`：`diagnostic_msgs/DiagnosticArray`。
- 点字段：`x`、`y`、`z`、`radial_velocity`、`snr_db`、`confidence`、`track_id`。

厂商 SNR 是相对线性值，当前规范化 CSV 的 `snr_db` 字段不能直接把它当作绝对 dB。真实解析器应保留原始 SNR，同时在转换层明确单位和来源；`confidence`、`track_id` 若协议帧没有对应字段，必须按“未提供/推导”标记，不能伪造为厂商原值。

## 下一次硬件采集必须保存

1. 设备标签、准确型号和固件版本截图；
2. 上位机端口、波特率和开始采集时间；

拿到原始字节流后再实现并验证厂商帧解析器，生成规范化 CSV，再接入现有 ROS 2 回放/观察链。`enable_mmwave_dynamic_mask` 在型号、帧解析、时间戳和外参通过验证前保持 `false`。
