# 性能与资源验证方案

核对日期：2026-10-15。本轮没有目标机性能实测。以下为执行方案与统计口径，非已达成指标，也不是新增比赛承诺。

## 一、基线环境

每次记录硬件型号、内存、系统及 ROS 版本、JetPack/CUDA/TensorRT/相机 SDK、功耗模式、温度、散热、运行包清单、地图宽高、输入数据率、网络方式和源码标识。

本轮 Python 离线测试运行在 Windows，其耗时不能代表 Jetson 帧率或导航响应。不同功耗模式、地图大小和模型版本不能直接混成同一性能基线。

## 二、指标定义

| 指标 | 采样方式 | 判定方式 |
| --- | --- | --- |
| 桥接请求延迟 | 只读请求的客户端单调时钟起止 | 报 p50/p95/max、失败数和样本数 |
| 状态推送间隔 | 客户端接收时间差 | 对比配置节奏，报抖动和断线；不等同传感器频率 |
| 地图快照开销 | 固定原图、缩放参数，记录编码耗时和 PNG 字节数 | 对照修改前后，必须先确认像素及元数据语义相同 |
| CPU、内存、温度 | 目标机只读系统观测 | 报稳态、峰值和持续增长趋势 |
| GPU 负载和图像率 | 目标机现有采集或推理日志 | 分开采集帧率、处理帧率和丢帧 |
| 上传吞吐与恢复 | 固定资产、摘要、网络条件及远端确认 | 分开排队、传输和最终确认耗时 |
| 定位水平误差 | 估计位置与独立真值，同时间和坐标系 | 使用现有评估器，报样本数、均值、RMSE、p95、极值 |
| 高程误差 | 独立 Z 真值与有效估计 | 缺失或非有限 Z 不当成零误差 |
| 重定位 | 逐次记录 RECOVERED、FAILED、MANUAL_REQUIRED | 成功率含所有有效尝试，耗时仅成功且有值 |
| 特征重复率 | 相同坐标系的连续帧和固定匹配距离 | 区分总体池化值、逐帧均值与最小值 |

若原始数据中出现 NaN/Infinity，先标记数据质量问题。不能因统计函数返回数值就认定数据有效；本轮没有扩大输入校验策略。

## 三、当前统计约定

- 位置误差为二维欧氏距离；RMSE 为误差平方均值的平方根。
- 位置评估器的中位数是排序后索引 count//2 的值；偶数样本取上中位数，不是两中项平均。
- 位置 p95 使用 min(int(count*0.95), count-1) 作为零基索引，不是插值百分位。
- 重定位耗时中位数同样取上中位数，保留旧报告口径。
- 重定位人工介入不算自主恢复；无成功耗时返回空值，不补零。
- 特征重复率使用 2M/(N1+N2)，空特征帧对单独统计，不视为完美重复。

上述公式来自现有实现，不在本轮“纠正”为其他统计库默认值。若未来要改，必须新决策、明确报告版本并重算历史对照。

## 四、可重复采样流程

1. 固定输入与依赖版本，保存原始文件摘要；实测与合成数据分目录。
2. 记录冷启动，预热完成后再开始稳态采样，预热时间写入记录。
3. 默认计划做三轮独立采样，每轮稳态观察十分钟；现场资源不足时记录实际时长，不补样本。
4. 先串行观察单链路，再在受控场景观察组合负载，不能为压测启动机器人运动。
5. 同一基线修改前后使用同一输入；系统温度或网络变化明显时重新对齐条件。
6. 原始序列保留时间戳，统计报告列出失败、超时和排除样本及原因。

三轮和十分钟是建议的采样计划，不是已完成工作，也不是硬性比赛阈值。

## 五、通过标准与回归判断

首先要求不破坏安全和数据语义。性能阈值在实际任务、截止时间和设备约束明确后冻结；本轮不凭空指定 FPS、内存和延迟上限。

尚无冻结阈值时只能报告前后差异与波动，不能写“性能达标”。发现明显持续增长、消息长时间过期、队列不再恢复或接口错误增多时，停止扩大负载并记录问题。

禁止用减少输入样本、跳过错误帧、把未知区改为空白、禁用控制锁或降低安全门槛换性能数字。
