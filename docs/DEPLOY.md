# 部署与回滚手册

核对日期：2026-10-15。本轮只完成本地修改与离线验证，没有连接机器人、上传文件、激活发行包或重启服务。

## 一、环境与前置条件

目标栈依据项目说明为 Ubuntu 22.04、ROS 2 Humble、Jetson。实际系统、JetPack、设备与模型版本需现场记录。Python 依赖优先核对各包 package.xml，不能根据 Windows pip 环境推断目标机依赖齐全。

部署前必须确认：

1. 发行对象是已提交快照还是当前工作树，未提交修改是否纳入有明确清单。
2. 保存原始源码、地图、路线、运行配置和平台数据的独立备份，记录摘要。
3. 发行包、校验侧车文件及本地定向测试结果一致，包内没有密钥和大型模型。
4. 目标机有足够磁盘，SSH 身份与目录正确，当前任务由现场人员安全结束。
5. 部署、激活、服务重启和运动验收分开授权与执行；本轮授权不等于现场运动授权。

## 二、阶段边界

| 阶段 | 操作 | 状态与限制 |
| --- | --- | --- |
| 本地准备 | 清单、补丁、离线测试、打包、哈希 | LOCAL_ONLY，不代表已写入 |
| 发行包安装 | 上传、校验、解包到新目录、预检 | 成功后逐项记录 TARGET_WRITTEN 与预检范围 |
| 激活链接 | 切换活动发行路径 | 有文件系统副作用，不等于运行进程更新 |
| 运行装载 | 现场人员管理服务或进程 | 可能使控制链可执行，需安全条件 |
| 目标机观测 | 构建、日志、ROS 图、TF 和新鲜度 | 对应项目可记 TARGET_VERIFIED |
| 实际任务 | 现场人员执行受控流程 | 独立保存现场验收，不能用预检替代 |

## 三、本地准备

在仓库根目录做只读检查，输出包含已有其他改动，不能随意清空工作树：

~~~powershell
git status --short
git diff --check
git diff --stat
~~~

本轮指定测试见 [测试计划](TEST_PLAN.md)。不运行全量 colcon test，不安装或升级全局依赖。

发行包必须列出源码、配置、脚本、文档和所需接口，排除 build/install/log、缓存、令牌、模型权重及不必要采集数据。Git 忽略规则不是敏感数据审计，也不是完整备份策略。

本手册不提供自动打包写入脚本，以免把当前其他未提交文件无选择地纳入交付。确认包清单后再执行实际打包；仅 git archive HEAD 无法交付本轮尚未提交的内容。

## 四、现有安装通道

入口为 `scripts/deploy_release_from_windows.ps1`。它要求 RobotHost，可选 RobotUser、ArchivePath、Commit 和 ExpectedSha256；没有显式摘要时读取归档旁的 .sha256 文件。它会核对哈希，探测 SSH，上传归档和安装脚本，并远端执行安装。这不是只读命令，本轮未执行。

远端 `scripts/install_release_on_robot.sh` 接受归档、发行名、源码标识和期望摘要。当前约定新目录为 `/home/nvidia/dg202611_ws_<标识>`，保护基础工作区 `/home/nvidia/ros2_DL`，拒绝覆盖已存在发行目录。归档中的必需文件包含 preflight、activate、integration、inspection、models service、采集脚本及基础包构建文件。

安装预检会构建 ylhb_base、ylhb_llm 并运行已有多组模型和证据测试。它不是本轮定向测试的别名，也没有覆盖全部桥接包。安装成功会生成 DEPLOYMENT_RECORD.json、部署日志及源码摘要清单，运动测试字段保持 false。

安装器的预检会执行构建、脚本和离线场景。本轮没有核验其在实际目标环境的全部副作用，不能把 preflight 当只读诊断或直接运行作安全证明。

## 五、构建与兼容检查

`scripts/build_on_jetson.sh` 默认使用 `WS_DIR=$HOME/ros2_DL`、ROS Humble、Release，并执行全工作区 colcon build。为避免误用保护目录，本轮不运行此脚本。

若仅验证本轮数据处理变更，在已审查、独立的发行目录中可人工选择桥接包构建：

~~~bash
source /opt/ros/humble/setup.bash
PYTHONNOUSERSITE=1 colcon build --packages-select ylhb_mobile_bridge --symlink-install
~~~

该命令会在当前目录写入构建产物，执行前必须确认目录与依赖包已经准备；它不安装缺失依赖，也不证明自定义接口或全系统构建完整。评估器脚本仍需按测试计划单独验证。

当前 Windows Pydantic 为 2.13.4，而 schemas 使用 regex 参数，本机已复现 API 模型导入失败。部署前必须在目标环境实际导入并验证，不能擅自升级全局 Python 来规避。具体结果见 [变更说明](CHANGELOG_20261015.md)。

## 六、激活与运行

活动链接由 `scripts/activate_dg_release.sh` 管理，链接为 `/home/nvidia/dg202611_ws`。它核对部署记录、预检日志、安装环境和服务入口，拒绝覆盖非符号链接；通过临时链接切换，并输出前一个发行路径。

切换链接不会自动重启当前进程。若服务仍在运行，新启动与旧进程可能加载不同版本。由现场人员在安全状态下处理进程装载，再记录只读观察。不要把链接指向新目录写成“机器人已运行新版本”。

不在本手册中给出可直接复制的运动启动、巡逻恢复或速度发布命令，现场操作依据已核对的专题流程执行。

## 七、回滚

1. 发现不受控行为由现场人员立即使用物理急停，禁止依赖网络请求保证停稳。
2. 保存失败版本日志、当前与前一发行路径、数据目录和任务状态，不删除失败包。
3. 现场确认安全且前一发行符合安装检查后，用原激活脚本切回已记录的前一目录。
4. 由现场人员重载相关进程；Agent 仅观察已启动系统。
5. 重新核对版本、地图路线、数据库及待上传任务。源码回滚不自动回滚数据或数据库结构。

本轮不涉及数据库迁移；未来有迁移时须补充兼容性与恢复方案，否则不允许仅靠链接切换宣称可回滚。

## 八、部署记录与停止条件

使用 [验收模板](templates/ACCEPTANCE_RECORD.md) 记录包清单、哈希、前后目录、依赖、日志和执行者。哈希不一致、包缺文件、环境不兼容、备份缺失或控制链状态不明时停止部署，明确标记阻塞。
