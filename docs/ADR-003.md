# ADR-003：分层验收并对不可比较的证据明确拒绝

- 日期：2026-10-15。
- 状态：采纳；本轮实施两个离线输入校验修复及定向回归入口。
- 范围：离线统计、测试骨架、真实采集证据与交付措辞。
- 关联：[测试计划](TEST_PLAN.md)、[测试规范](好测试规范.md)、[变更草稿](../CHANGELOG_DRAFT.md)。

## 背景与问题

工程中同时存在合成场景、历史 CSV、真实采集工具、ROS 包测试、接口模拟和现场验收报告。它们各自有价值，但结论不能互相替代。一个纯 Python 测试能说明公式对给定输入正确，不能说明雷达正常；HTTP 返回接收不能说明机器人已到达；设备文件存在不能说明数据有效；上传进入队列不能说明远端已经收到。

这次源码检查还发现两个可以本地复现的问题。第一，重复率汇总入口验证匹配距离，但公开的单帧对入口没有同样验证。负距离在平方后仍可能匹配点，NaN 和无穷大也会产生误导结果。第二，一帧为空间点、另一帧为旧 ID 时，匹配逻辑退回旧 ID 路径，可能把不兼容数据记成零重复率。这样的结果看起来是性能下降，实际上连比较前提都没有满足。

如果只添加“能导入模块”或“函数存在”的测试，这两种错误不会被发现。若直接用这些结果评价真实系统，则可能把数据格式问题解释成算法效果问题，甚至错误判断是否完成比赛要求。因此需要同时明确测试设计与证据表达。

## 决策

采用三层结论：本地确定性检查、目标机运行观察、现场真实流程。必要时单列远端往返。每一层都记录输入、环境、执行动作、输出和限制，不将层级自动升级。本文与 ADR-004 的文档证据分层保持一致，但本条补充具体的离线输入拒绝语义及测试入口。

本轮在已有重复率测试文件补行为案例，先运行并观察失败，再修改最小实现。单帧对与汇总入口共用匹配距离验证；非空帧对混用空间点和旧 ID 时抛出明确异常。合法空间点匹配、合法旧 ID 匹配和原有聚合公式保持不变。空特征帧的原有未定义处理继续保留，不将空输入包装成完美匹配。

新增脚本只调用两个明确列出的离线测试文件，并传回 pytest 退出状态。脚本从自身位置定位仓库，因此不要求当前目录恰好是仓库根目录。不自动安装依赖、不连接网络、不启动 ROS，不递归执行全部测试，也不采集任何机器人数据。

测试中的临时 CSV 是验证文件读取、统计、JSON 输出和错误码的受控样本，不能存入真实证据目录冒充采集结果。真实要求评估继续坚持证据不足时不给 PASS；本轮不降低清单、来源和预冻结协议要求。

## 考虑过的方案

方案一是对所有输入尽量容错，把缺字段、非法距离或格式不一致转换成默认值。它能让程序总有数字输出，但会掩盖数据污染，因此拒绝。尤其不能把缺证据变成零误差、零耗时或成功。

方案二是编写大量 ROS 假节点，模拟完整启动流程，然后据此宣称集成完成。它能测试部分接口，但无法证明真实 discovery、TF、设备、生命周期与时序有效，而且维护成本高，因此不作为本次完成标准。

方案三是只测确定性逻辑，把实机与远端验收写成明确人工步骤，未执行项保持未证明。它不能给出整车完成结论，却能提供可信的本轮回归证据，因此采纳。

## 后果、限制与错误处理

结果更可解释：非法匹配距离和不同数据格式不会再悄悄进入有效统计。调用者现在可能收到过去没有抛出的 ValueError，这是有意收紧的非法输入兼容性；需要修正输入，而不是捕获后继续使用旧报告。CLI 对对应错误返回非零退出码，批处理应停止或将该项明确记为失败。

代价是定向检查只覆盖列出的行为，不覆盖全仓库、GPU、设备驱动或真实运动。已有其他未提交修改不是本次修复，不应混在本轮变更说明里算作新成果。缺少 pytest 时，使用当前解释器安装到用户选择的虚拟环境；脚本本身不会更改全局环境。

## 验收与后续扩展

验收必须同时包含修复前的失败、修复后的同一案例通过、有效输入行为保持，以及脚本的退出状态。CSV 到 JSON 的临时文件流程属于真实运行过的离线流程；对它的结论只能是离线链路可运行，不能写成实机通过。

现场人员仍需完成设备数据、TF、导航生命周期、地图绑定、任务终态、急停效果和远端资产确认。每条记录带时间、设备、版本与原始文件。将来增加新的评估格式时，先定义能否与旧格式比较及坐标转换依据，再修改实现和契约；没有明确转换就拒绝混算，而不是继续扩大自动降级行为。
