# ADR-006：本地与云端控制必须分开鉴权并等待执行反馈

- 日期：2026-10-15。
- 状态：记录现有实现，本轮不改变权限配置。
- 依据：mobile_bridge_server.py、platform_api.py、桥接参数和既有平台存储。

## 背景

桥接同时提供本地 APP、调试路由、平台入站接口和云连接。它们的令牌、响应格式和控制门槛不同。把“服务可达”“令牌有效”“命令接受”“机器人完成”合并，会导致权限混乱和误报。

## 决策

1. 本地接口的可选鉴权和平台始终要求的 Bearer 分别表达；外层鉴权叠加时两层都必须满足。
2. 同时配置云端地址和机器人令牌后，平台入站部署、启动与控制默认受限，保留现有 INBOUND_CONTROL_DISABLED 行为。
3. 不为测试开启 YLHB_ALLOW_INBOUND_PLATFORM_CONTROL，不自动改变 require_token、监听或网络策略。
4. accepted、STARTING 和 PENDING_ROS 只是异步过程状态，客户端继续等待可关联的执行反馈。
5. HTTP stop、巡逻取消和 Action 取消不代替物理停稳观察，更不代替物理急停。

## 备选方案

| 方案 | 不采用原因 |
| --- | --- |
| 所有入口共享一层隐式鉴权 | 与当前实现不符，容易漏掉平台或外层检查 |
| 联调时关闭令牌或放开入站控制 | 把便利置于控制权边界之上 |
| API 返回 200 就显示任务成功 | 业务错误可能仍为 200，异步任务还未执行 |
| 完全禁止本地控制 | 改变现场操作目标，未经本轮要求 |

## 后果

客户端必须处理不同响应格式、叠加凭据和异步状态，不能只写一个“请求成功”分支。文档多一些，但能避免假完成和双控制源争抢。

当前监听、匿名本地接口和通配 CORS 仍有部署风险，参见 [安全说明](SECURITY.md)。本决策记录边界，不意味着这些风险已经整改。

## 验证要求

- 离线接口测试检查无凭据、错误凭据、两层鉴权和云入站拒绝；不能向真实 ROS 发布命令。
- 现场执行由人员完成，记录请求标识、命令标识、执行标识、接收时间和最终状态。
- 失败、断线和人工接管都不能被改写为自主成功。

如果未来合并认证、改用角色权限或更换控制所有权，需要新的接口版本或迁移说明，并新增决策替代本文。
